# Documentation Hub

This repository uses the OIL documentation standard.

## Purpose
The `/docs` folder is the single entry point for project documentation. It helps new and existing contributors find architecture, plans, runbooks, onboarding notes, and workflow details quickly.

## Structure
- `architecture/`: system design, diagrams, integration maps, and technical decisions.
- `plans/`: roadmap items, implementation plans, and project milestones.
- `runbooks/`: operational procedures, troubleshooting, and incident response.
- `workflows/`: CI/CD workflow inventory, triggers, and usage guidance.
- `onboarding/`: how to get productive quickly in this repo.

## Documentation Rules
- Keep docs close to the code they describe, but index them from `/docs`.
- Prefer short, task-oriented docs over long narrative documents.
- Every major change should update at least one relevant document in `/docs`.
- Cross-link related docs to avoid duplication.

## Getting Started
1. Read `onboarding/README.md`.
2. Review `architecture/README.md` for system context.
3. Check `workflows/README.md` and `workflows/catalog.md` for automation.
4. Use `runbooks/README.md` for operation and support tasks.
